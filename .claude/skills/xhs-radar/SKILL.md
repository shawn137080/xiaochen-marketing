# 每日选题雷达

目标只有一个：**今天给用户 5–8 个值得做的选题，每个都有数据依据**。宁可少给，也不要凑数。

所有数据都在 `vault/`（Obsidian vault，用 Git 同步）。命令在仓库根目录执行。

## 0. 读定位
先读 `vault/00-定位/账号定位.md`。后面所有判断（匹配度、角度、口吻）都以它为准。

## 1. 采集对标账号和关键词（Apify）
```bash
npm run xhs -- doctor
npm run xhs -- sync
npm run xhs -- search <从「关键词」里挑 2-3 个，每天轮换>
```
- `doctor` 会列出缺「主页链接」的对标账号。如实告诉用户哪些账号没抓到，以及怎么补（见账号定位页的说明）。
- 网络不通或缺 token 时，直接告诉用户卡在哪，然后继续第 2 步。**不要编造数据。**
- 打分逻辑在 `scripts/xhs/score.mjs`。「选题分」看的是相对账号自身水平的超常倍数、赞粉比、量级、藏赞比和评赞比；「标签」里有 爆款、低粉爆文、干货收藏型、讨论型、正在涨。

## 2. 扫热点（agent-reach）
先运行 `agent-reach --help` 和 `agent-reach doctor`，看哪些渠道可用，再按实际语法调用。不要猜子命令。
- **小红书**：用关键词搜热门笔记（需要本机 Chrome 已登录小红书，只能在用户电脑上跑）。把结果存成 JSON，再导入打分：
  `npm run xhs -- import <文件.json> --source 热点:小红书`
- **英文一手源**（X、Reddit、YouTube）：搜最近 48 小时的 AI 新工具、新功能、爆火用法。这是**信息差选题**的来源，也是北美博主的天然优势。
- 写入 `vault/30-热点/YYYY-MM-DD.md`。每条写：平台、标题、链接、热度信号（赞数/转发/排名）、「对北美打工人/小老板有什么用」一句话。没用的不写。
- agent-reach 没装或不可用时，跳过这一步并说明原因。

## 3. 拆解高分笔记
```bash
npm run xhs -- top --days 2 --min 50 --limit 8
```
对排名前 3–5 篇，按 `xhs-breakdown` skill 的维度做**精简版拆解**，写进该笔记的「## 拆解」段，并把 frontmatter 改成 `拆解: true`。
挑笔记时优先看标签：爆款 > 低粉爆文 > 正在涨 > 干货收藏型。高分但和定位无关的（比如纯技术、写代码）直接跳过。

## 4. 生成选题
素材来源按价值排序：
1. **已验证的爆款，换我的角度**：拆过的高分笔记。
2. **评论区里没人回答的问题**：可以用 `npm run xhs -- comments <链接>` 抓评论。
3. **英文一手热点，抢时间差**：要在 24–72 小时内发。
4. 定位里的人群痛点。

每个选题必须过这四关，有一关不过就不要：
- **人群**：北美、不太懂 AI 的打工人或小老板，看到会觉得"这说的是我"？
- **结果**：看完明天就能用上，能说出省了什么、赚了什么？
- **验证**：有数据依据（某篇对标爆款、热点热度、评论需求）？
- **差异**：我能实测、身在北美、能用美区工具，别人做不了或没做？

选题公式：**人群 × 场景 × 工具 × 结果**，例如「餐馆老板 × 回复 Yelp 差评 × ChatGPT × 5 分钟一条不得罪人」。

先 `ls vault/40-选题库` 查重，再按 `vault/_templates/选题.md` 的结构写进 `vault/40-选题库/<选题短名>.md`：
- `推荐分` 0–100，是你的综合判断：数据验证 40、人群匹配 30、差异化 20、执行难度 10。
- `来源笔记` 用 `[[文件名]]` 链接对标笔记，`来源热点` 写链接。
- **不抄**：标题、结构可以借鉴公式，内容和案例必须是自己的。

然后加入看板：
```bash
npm run xhs -- kanban-add 待选 "[[选题短名]]"
```

## 5. 汇报
在 chat 里给用户：
- 今天最推荐的 3 个选题：每个附一句"为什么现在做"和数据依据。
- 对标账号的异动：粉丝暴涨、某篇正在涨。
- 没跑通的步骤和原因。

## 6. 同步到 Obsidian
```bash
git add vault && git commit -m "雷达: YYYY-MM-DD 选题 N 个" && git push
```
用户的 Obsidian Git 插件拉取后就能看到。
