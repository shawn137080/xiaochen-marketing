# 对标笔记拆解

## 拿到内容
1. 用户给的是 vault 里的笔记（或 `note_id` 能在 `vault/20-对标笔记` 搜到），直接读文件。frontmatter 里有赞、藏、评、超常倍数、赞粉比等数据。
2. 用户给的是链接，但 vault 里没有：
   - 先试 `agent-reach read <链接>`，或者 agent-reach 的小红书渠道。
   - 再试 Apify：把 `xhs.config.json` 里的 actor 换成 note_detail 模式。
   - 都不行就请用户把正文粘贴过来。
   拿到内容后存成 JSON，用 `npm run xhs -- import <文件> --source 手动拆解` 导入，这样它也会被打分、进库。
3. 评论区：`npm run xhs -- comments <链接> --limit 50`。失败就跳过，并注明"未看评论"。
4. 先读 `vault/00-定位/账号定位.md`。

**诚实原则**：没看到封面图就写"未看图，仅凭标题推断"；没拿到评论就不要编评论区痛点。

## 写入格式
写进该笔记的 `## 拆解` 段（替换掉里面的注释），frontmatter 设 `拆解: true`，并加上 `拆解日期`。

```markdown
## 拆解
**一句话**：<这篇到底在卖什么价值，给谁>

**为什么火**：<结合数据，比如超常 4.2 倍（这个账号平时的 4 倍），藏赞比 1.3 → 干货收藏型；不要只复述数字，要解释>

| 维度 | 这篇怎么做的 | 可复用的公式 |
|---|---|---|
| 标题 | | 例：「人群+痛点+数字结果」 |
| 封面 | | |
| 开头钩子（前 3 秒/首图） | | |
| 结构 | | |
| 价值类型 | 实用 / 情绪 / 社交货币 / 信息差 | |
| 结尾互动 | | |

**评论区需求**（按点赞排序）
- 高频问题：
- **没人回答的问题** → 选题机会：

**我怎么做**（3 个角度，必须贴合北美打工人/小老板，且是我能实测的）
1. <选题一句话> —— 为什么我做比原作者更合适
2. 
3. 
```

最后问用户：要不要把其中某个角度直接存成选题？要的话按 `xhs-topics` skill 处理。
